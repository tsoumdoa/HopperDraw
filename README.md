# HopperDraw

Persistent annotation lines, polylines, frames, curves (including freehand), and groups on the Grasshopper canvas in Rhino 8. Annotations belong to a **Hopper Draw** component and use absolute canvas coordinates. They stay in place when the component moves.

## Start drawing

1. Build the plugin for your Rhino runtime (see Development), then load the resulting `hopperborder.gha` through Grasshopper's component libraries folder and restart Rhino. Keep one copy installed.
2. Place **Hopper Draw** from **Params > Util**. Leave Active and Show enabled. Choose a tool in the component's **Drawing > Tool** menu or through input M. A wired M input controls the tool and disables menu choices.
3. Focus the canvas and press and release **D twice**. The component footer shows `ON`; a bottom-centre pill shows the tool, pen preview, and the next action. Use **Drawing > Pen** to set the next-shape style.

Line and frame support **press-drag-release** and **click-click**. Polyline and curve add a vertex per click. **Enter** or **double-click** finishes an **open** stroke without a duplicate endpoint. With at least three distinct vertices, click the first point to close; a ring highlights it nearby. **Backspace** removes the last draft vertex. **Shift** snaps segments to 45-degree increments and makes frames square.

**Freehand (M=4)** uses hold-drag-release; Curve keeps click-to-add behavior. Freehand ignores Shift, Enter, Backspace and click counts. Release creates one curve, or closes a meaningful loop when released within the start ring (9 screen pixels). Clicks and tiny strokes create nothing. Escape, focus/capture loss, document changes, disabling the owner, or switching tools discard a held stroke, including its trailing mouse-up. The pen's **Smoothing > Low / Medium / High** choice is session-only (Medium by default). Sampling uses the current viewport during auto-pan; processing captures gesture zoom, resamples at about 2 screen pixels, averages with a 3/5/9-point kernel, and simplifies at 0.75/1.5/3 pixels. Open endpoints stay fixed; closed loops use cyclic smoothing and split-loop simplification. Raw samples are bounded at 8,192 and output at 2,048, with coarser resampling for exceptionally long strokes and dense points restored when spline overshoot exceeds the error budget.

**Escape** cancels the current draft first; another press exits drawing mode. Completed shapes remain. The pen survives completion, cancellation, and exit/re-entry; only pen choices or **Reset pen to component defaults** change it. Drawing creates canvas annotations, with no outputs or Rhino model geometry.

## Inputs (stable order)

| Input | Default | Meaning |
| --- | --- | --- |
| Active (A) | true | Enable annotation editing and double-D activation. Inactive annotations still display. |
| Show (S) | true | Display annotations. Hiding cancels drawing. Locking the component also hides its annotations. |
| DrawMode (M) | 0 | 0 Line, 1 Polyline, 2 Frame, 3 Curve, 4 Freehand. Changing mode cancels an unfinished shape. |
| Color (C) | Black | Default annotation color; shapes can override it. |
| Thickness (T) | 8 | Base width in canvas units, clamped to 0.1-1000. Effective base times multiplier is capped at 1000. Non-finite input uses 8. |
| LineType (L) | 0 | 0 Solid, 1 Dash, 2 Dot, 3 DashDot, 4 DashDotDot. |
| DrawOrder (O) | 1 | 0 below wires/components (Groups channel); 1 above (Overlay). Previews and handles always use Overlay. |

Out-of-range mode, order, dash, or thickness inputs produce runtime warnings and safe values. Stroke widths scale with canvas zoom; handle sizes and picking tolerance stay approximately constant in screen pixels.

## Editing and menus

Click an unselected annotation to replace the selection. Press an already-selected body to preserve and move the entire mixed selection: annotations across owners and selected native GH objects. **Shift-click** adds, **Ctrl-click** removes without dragging the removed shape, and **Shift+Ctrl-click** toggles. Selected handles edit that annotation's geometry. A plain click on a previously unselected native GH object clears annotation selection; pressing an already-selected native object preserves it.

Empty-canvas selection uses GH's own selection rectangle: left-to-right **Window** requires the entire stroke inside; right-to-left **Crossing** includes strokes intersecting the rectangle, including closing edges and curve extrema. At release, Shift adds, Ctrl removes, and other modifier combinations replace. A plain empty-canvas click clears selection. **Ctrl+A** (GH Select All) also selects readable annotations and **Ctrl+D** (GH Deselect All) also clears them; GH still runs its own command, and **Ctrl+Shift+A** (GH Grow Selection) is untouched. Pressing a native grip, slider, toggle or other control that does not change GH's selection keeps the annotation selection; a press that replaces GH's selection replaces it too. **Delete** (or Backspace outside a draft) removes a mixed selection in one undo record. Text editing retains native handling.

Drag an annotation body or a selected native object to move the mixed selection. Selected native groups expand to their non-group descendants. Shift constrains whole-selection movement horizontally/vertically. Shift snaps endpoint and polyline/curve vertex edits to 45 degrees relative to their anchor; frames retain their starting aspect. Annotation-led moves use press snapshots and record only on a changed release. **Escape, focus loss, capture loss, or document switching reverts the gesture and records nothing.** A native drag without selected annotations is left entirely to GH. Polyline/curve drafts survive focus loss and other mouse buttons between clicks; switching documents cancels them. A click or a drag returning to its starting geometry creates no annotation undo record. Undo/redo clears transient annotation selection.

Native-led dragging follows actual native pivots, including snapping, Shift constraints, and auto-pan. Annotation snapshots join the verified native drag record for one-step undo. If GH supplies no matching record, the annotation movement reverts. **Alt copy mode copies only native objects; selected annotations return to their start.** A canvas paint callback before the Groups channel provides guarded translation-only synchronization during auto-pan; no timers are used. These host behaviors still require the live Rhino checks below.

**Right-click a shape** for **Stroke > Color / Thickness / Line type / None**. None hides the stroke; toggle it again to restore it. Thickness presets remain 0.5x/1x/2x/3x/5x. Color includes named swatches, five session recent colors, Custom…, and Use component color.

**Fill** applies to frames and closed polylines/curves (including freehand). Choose None, a color, Opacity (10/25/50/75/100%), Hatch, Hatch scale (0.5x/1x/2x/4x), and Hatch background. With Hatch=None the color is a solid fill; otherwise it is hatch ink over the optional background. Color alpha is multiplied by opacity. Fill=None turns off the entire fill layer while retaining dormant hatch settings. Background is ignored for solid fill. Patterns are Diagonal (ANSI31), CrossHatch, Concrete, Earth, Insulation, Brick, Grid, Dots, Horizontal and Vertical. Patterns use canvas units and canvas-origin phase, independent of zoom, with a 0.75-unit ink width; only visible bounds are generated and extreme primitive counts use a solid-ink fallback. Fill never inherits component color.

Style commands visit selected leaves across owners in one undo transaction, preserve nested group styles, and skip unchanged values. Mixed selections fill only closed eligible leaves; checks reflect that subset. **Use selection style for drawing** copies the complete uniform stroke/fill/hatch tuple and is disabled if any field is mixed. Selection styling otherwise leaves the pen alone. **Drawing > Pen** has Stroke, Fill and Smoothing; pen fill is disabled for Line and applies on completion only when a shape is closed. A completed shape with no effective paint is discarded with a brief HUD notice and no undo record.

A visible fill makes the whole interior pickable, including gaps between hatch marks; native-object priority is unchanged. Crossing selection also catches a rectangle wholly inside a filled region. Hidden stroke width does not enlarge window-selection bounds. Fully invisible shapes remain pickable only near the boundary, and have a thin dashed ghost when selected, hovered, or owned by the active drawing component. Selection outlines always follow the shared boundary, including self-intersecting curves (winding fill rule).

The same menu provides Bring to front / Send to back (within each owner, preserving relative order), Group / Ungroup, Duplicate, and Delete. Cross-owner grouping is disabled with an explanation. Groups remain pure containers, retaining each child's styles. Grouping uses the highest selected slot after removing the children: `[A,B,C,D]`, grouping A+C gives `[B,Group(A,C),D]`. Ungroup selects the restored children alongside other selected shapes. Duplicate offsets copies by 30 canvas units and assigns new shape GUIDs. Unreadable records block geometry movement and duplication atomically across affected annotation owners.

Right-drag on an annotation still pans; Ctrl+right-drag zooms. A contextual click changes selection only at release (Shift adds). In drawing mode, right-click empty canvas for Tool, Pen, Reset pen, and Exit drawing mode. The component menu reuses **Drawing** and **Selection** builders, plus Select all annotations, Select unreadable annotation records, and Clear all.

Cursors identify drawing, movable bodies, and handles. Selected strokes have a light halo and dashed green outline without changing their stored colors. Annotation double-clicks outside drawing mode suppress GH search and leave geometry unchanged. Components, parameters and grips retain hit priority over annotation bodies; selected annotation handles take priority over native objects. A GH group's interior counts as empty canvas, so annotations inside groups can be picked, edited and drawn there; only a group's edge band (12 canvas units, 20 at the top) is native. HopperDraw changes the cursor only over its own targets and in drawing mode, never over GH's own wires, grips or controls. Overlay annotations precede Groups-channel annotations, then later owners and later shapes win.

Multiple components retain separate shape lists and selections; all eligible owners participate in editing. Double-D chooses the selected editable HopperDraw, then one with an annotation selection, then the first eligible owner. The drawing owner retains its drawing session. Read-only, inactive, hidden, and locked owners cannot capture input. Plain D remains reserved only while activation is eligible; text controls, native shortcuts, focus changes, and document switches interrupt activation.

Shape edits use canvas-only undo without requesting a solution. Tool input changes and native deletion may solve normally. Undo history is in memory and does not survive reopening a file. Windows uses a per-canvas HWND hook and an application message filter before menu preprocessing. The existing non-Windows event path remains unsupported and unverified. Public pinned GH APIs do not expose its internal `GH_CanvasMenuStrip`; annotation menus use `ContextMenuStrip`, the same native WinForms base, with ordinary menu items. GH exposes no public abort/cluster icon hit tests, so editing yields conservatively in aborted documents and the cluster icon's screen corner.

## File format and recovery

This release uses annotation **format v1**, in a dedicated `HopperDraw` chunk with a `FormatVersion` value. Each shape has an indexed sub-chunk and a persistent GUID; groups recursively contain child lists. GUIDs survive save/load and undo; copies receive fresh IDs. Copy/paste rekeys the standard v1 ID envelope even for opaque records; future-format payload contents remain untouched. No legacy flat-key reader or downgrade format is provided. Files from 0.1.6 and earlier are unsupported. **Files saved by this version cannot be read by HopperDraw <=0.1.6**: those readers omit the component, so do not re-save these definitions with an older plugin. The owner sets the package version when preparing the release.

`FormatVersion` is a **major format version**. Breaking changes require a new major value and are retained opaque/read-only by this reader. Additive optional fields keep the major value: unknown items (including indexed keys) and sub-chunks in readable components, shapes, and shape lists are preserved verbatim through save/load, duplication, and undo. Known fields reflect edits. Additive data must remain safe for an older reader to ignore; features requiring new geometry semantics need a major version change.

Required kind, GUID, geometry/cardinality, and coordinate checks prevent damaged data becoming guessed geometry at the origin. The existing optional stroke keys use defaults with load diagnostics when missing. New additive stroke-visibility and fill/hatch keys default silently when absent; present invalid types, non-finite values, or unsupported hatch enums retain the record opaque. Component load diagnostics persist through edits and solutions until the next successful read or Clear all; clear/undo restores them. Shape diagnostics remain until the affected records are removed or successfully re-read. Invalid/unknown records remain opaque in their original list positions and produce a persistent runtime warning. They are retained on re-save and are not painted. Any subtree containing opaque records blocks geometry transforms and duplication, with feedback, so readable children cannot drift away from unreadable siblings. Use Select unreadable annotation records, then Delete, to remove top-level opaque records safely; ungroup first to expose nested records. Deletion and Clear all are undoable. An unsupported format or damaged list keeps the entire raw annotation payload read-only on re-save. Open it with a compatible version to resolve it; this release does not interpret or rewrite it as v1. A missing `HopperDraw` annotation chunk loads as an empty, editable component with a one-time notice that pre-v1 formats are unsupported; GH component metadata is never captured as annotation data. Failures reading base Grasshopper metadata and wires retain GH's native failure behavior; only annotation parsing has recovery.

The additive v1 keys are `StrokeVisible` (Boolean, default true), `HasFillColor` + `FillColor` (Int32 ARGB, default none), `FillOpacity` (Double 0.1–1, default 1), `Hatch` (Int32 0–10 in the pattern order above, with None=0), `HatchScale` (finite Double >0 and <=1,000,000, default 1), and `HasHatchBackground` + `HatchBackground` (Int32 ARGB, default none). Unknown and indexed extension data remain preserved. Smoothing and pen state are never archived.

Parsing is limited to depth 32, 20,000 shapes, 200,000 points, and finite coordinates within +/-10,000,000 canvas units. Exceeding a budget keeps the affected record or payload opaque. Raw unknown data is retained, so these are interpretation budgets, not a file-size limit.

## Development

Use Windows, Git, a .NET SDK supporting the declared targets, and the .NET Framework 4.8 runtime for the console tests. NuGet supplies the pinned Rhino/Grasshopper reference assemblies. The assembly/project name remains `hopperborder`; component and assembly GUIDs and all seven parameter slots remain unchanged.

```powershell
pwsh -NoProfile -File scripts/install-hooks.ps1
pwsh -NoProfile -File scripts/verify.ps1 -Quick
pwsh -NoProfile -File scripts/verify.ps1 -Full
```

Quick builds `net8.0-windows` Debug and runs every project under `Tests` by exit code, plus the hook snapshot script suite. Full builds Release for `net8.0-windows`, `net7.0-windows`, `net7.0`, and `net48`, then runs all tests. Both check that `yak/manifest.yml` matches the project version. Test projects are included in `hopperborder.slnx`; tests use the real plugin sources and GH assemblies without constructing a headless GH_Document.

The installer sets repository `core.hooksPath` to `.githooks`. Pre-commit exports the **staged index** into an isolated temporary directory and runs that snapshot's Quick verifier. Unstaged changes cannot hide staged failures or block a passing staged snapshot. Pre-push reads Git's ref updates from stdin and exports each distinct **outgoing commit tip** for Full verification, including branches other than the current checkout; repeated tips run once and deletion-only pushes need no build. Both paths use the normal shared NuGet cache and clean up their temporary directories without stashing or rewriting the working tree/index.

Git for Windows invokes the sh hooks, which prefer `pwsh` and fall back to `powershell`; both use `-NoProfile -ExecutionPolicy Bypass`. Calling `scripts/verify.ps1` directly verifies the current working tree. `Tests/Hooks/snapshot-tests.ps1` checks snapshot isolation and pushed-ref behavior in disposable repositories, and runs in both verification modes. Deliberate bypass: `git commit --no-verify` or `git push --no-verify`. There is no hosted CI.

`HopperDraw.cs` retains component state, persistence, and the unsupported fallback event path. `HopperDraw.Session.cs` bridges transient pen/tool/draft state. `Utilities/CanvasDrawingShortcut.cs` routes HWND input before GH and menu preprocessing; `CanvasAnnotationController` coordinates owners and native sessions; `HopperDrawInteraction` owns claimed gestures. `AnnotationMove`, `AnnotationDraft`, `AnnotationGeometry`, `AnnotationCommands`, `AnnotationMenuBuilder`, and `AnnotationFeedback` separate transactions, drawing, stroke selection, menus, and presentation. `Shapes/ShapeSerializer.cs` owns persistence. `Utilities/ShapeRenderer.cs` guards annotation/preview paint. `Utilities/ShapeEditUndoAction.cs` owns snapshots and canvas-only undo. `HopperDrawUIAttributes.cs` selects render channels and builds previews. Flattened annotation strokes used for picking, hover and window selection are cached per shape until its geometry changes.

Run the [live Rhino checklist](docs/live-test-checklist.md) before release. Headless tests cover archive/model/bitmap/input regressions, not host undo-server dispatch, native selection event ordering, DPI behavior, or actual .gh/.ghx document integration. Build success for all targets is not a claim of live Mac support.
