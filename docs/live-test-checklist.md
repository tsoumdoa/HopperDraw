# Reliability release: live Rhino 8 checks / PR notes

These steps require Rhino and are not recorded as executed by the headless verifier. Record Rhino version, runtime, Windows scaling, plugin SHA, and pass/fail for each section. Start with one installed HopperDraw build and a new unsaved Grasshopper definition.

## Save and reopen

1. Place HopperDraw and a slider connected to a panel. Draw a red line, blue dashed polyline, frame, open curve, and closed curve. Change leaf widths and group the first two shapes (group at index zero), then group that group with the frame.
2. Save as `reliability.gh`. Close the definition, reopen it, and compare geometry, order, group nesting, colors, dashes, and widths. Repeat as `reliability.ghx`. Pan until the HopperDraw component is offscreen while its distant annotations remain onscreen; annotations must still paint.
3. Re-save and reopen both files a second time. Confirm no HopperDraw warning for valid data. Test a definition with more than 1,000 shapes if available.
4. In a copy of the GHX, change a shape Kind to 99, keeping all other data. Reopen: unaffected annotations stay visible; a persistent warning names the unreadable record. Trigger several solutions; warning must remain. Save/reopen again and inspect that record's values/sub-chunks are unchanged and its list slot retained.
5. Repeat with a missing X coordinate array. Repeat on another copy with FormatVersion=99: annotation editing is disabled, the warning persists, and the annotation chunk survives re-save unchanged. Keep an untouched copy for comparison.
6. Return to a valid definition. Copy/paste the HopperDraw component. Inspect shape GUIDs in a GHX saved copy: supported shapes and nested children in the pasted component must have fresh IDs; the original IDs must stay unchanged. Undo/redo a shape edit and confirm its IDs remain unchanged. Shape IDs in opaque future data cannot be interpreted by this version.

## Undo/redo script (short smoke sequence for PR review)

1. Save the definition. Create one line, then Ctrl+Z: only the line disappears. Ctrl+Y: it returns. Repeat for frame, open/closed polyline, and open/closed curve.
2. Select a line; set 3x thickness, choose a Line type, and set color, separately. Undo/redo each action and verify exactly one style change each time. Repeat on a nested group with differently styled children.
3. Shift-select two separated shapes with an unselected shape between them. Group; undo; redo. Confirm highest-slot placement and original child order. Select two groups and a plain shape; ungroup and check the resulting selection references the correct children and plain shape. Undo; redo: geometry, order and IDs are restored, and the annotation selection is cleared (by design, undo/redo never restores transient selection).
4. Duplicate selected shapes; undo/redo. Delete selected shapes; undo/redo. Clear all; undo/redo. Include an opaque record in the Clear all check: undo restores its warning and raw data; redo clears them.
5. Drag a body through many mouse moves; one undo restores the starting geometry, one redo restores the final position. Repeat for every frame corner, a line endpoint with Shift, and polyline/curve vertices. Save, click without moving, and send a same-position move: no new undo record or modified asterisk. Hold Shift and make moves that snap to the same geometry: no new record until geometry changes.
6. Start a real drag, then Escape. It must immediately restore its start without a new undo record. Repeat with focus moving to Rhino, capture loss (switch applications), document switch, and component removal. Return and perform a fresh drag: it must still get one fresh record.
7. Select annotations plus native GH components, and drag an annotation body. Undo/redo must restore both annotation geometry and native pivots, update component bounds/wires, and leave native selection/interaction usable. Drag a selected native component with selected annotations: annotations must follow without a timer. Compare undo menu entries for unexpected extra native records.
8. Attach the counter below. Repeat shape editing plus undo/redo. The solution counter must not increase for canvas-only actions; input changes may solve normally. Reopening a file starts fresh undo history; do not expect undo-stack persistence.

## Render order, picking, and DPI

1. Draw thick lines across wires and across two components created before/after HopperDraw. O=0 must put all strokes below wires/components; O=1 above. Change GH object ordering and repeat. Both selections and in-progress previews must always remain on top.
2. Overlap annotations with different multipliers. Click their bodies and verify the topmost matching shape wins, including when they are group children. Group/duplicate/ungroup must not flatten child style.
3. Draw horizontal, vertical, and coincident lines; group and nest them. Check bounds and window selection away from the origin. Empty groups must not invent origin geometry.
4. Repeat selection and handle drags at 25%, 100%, and 400% zoom and at Windows 100%, 150%, and 200% DPI (restart Rhino after scaling if needed). Handles and the extra hit tolerance should remain similar in screen pixels; actual stroke width scales with zoom. Test near wide strokes, not just vertices.
5. Feed M=-1/99, L=-1/5/99, O=-1/2, T=0/-1/huge/non-finite (use a script for NaN/infinity). Expect warnings, safe values, and continuing canvas paint. Open a styled definition with the solver disabled and confirm it paints safely before solving.

## Repaint and ownership

Use a temporary C# script component with the following subscriptions (attach once, keep delegates to unsubscribe afterward):

```csharp
// Run in a live GH scripting component, not the headless test harness.
int paints = 0, solutions = 0;
var canvas = Grasshopper.Instances.ActiveCanvas;
var doc = canvas.Document;
System.Windows.Forms.PaintEventHandler onPaint = (s, e) => paints++;
Grasshopper.Kernel.GH_Document.SolutionStartEventHandler onSolve = (s, e) => solutions++;
canvas.Paint += onPaint;
doc.SolutionStart += onSolve;
// Inspect counters with a debugger or a separate non-solving UI callback.
// Cleanup: canvas.Paint -= onPaint; doc.SolutionStart -= onSolve;
```

1. With a large definition, move the pointer through empty canvas for 10 seconds, without drawing/dragging. HopperDraw should request no paints when hover is unchanged. Enter/leave a shape handle: a repaint is expected when feedback changes. Native GH hover/UI can paint independently; compare with HopperDraw inactive.
2. Draw and drag continuously: previews update while the solution counter stays unchanged. Repeat Undo/Redo. Monitor resource use during repeated previews; there should be no progressive accumulation of temporary pens/brushes.
3. Add a second HopperDraw, each with differently colored annotations. Select A, enter drawing with double-D, finish a shape: only A changes. Escape, select B, and repeat. Shift selection/drag/delete may span both eligible owners.
4. Switch documents while drawing and dragging; return and repeat double-D/drag. Only the current document's owner handles input. Disable Active, hide Show, lock/unlock, remove, undo removal, and close documents; verify no retained input capture or extra reactions.
5. Verify Ctrl/Alt native gestures, text editing, menu shortcuts, held/repeated D, and two distinct D presses. Double-click and Enter finish polyline/curve open; clicking the highlighted start closes; GH search should stay suppressed during drawing on empty canvas and work again after Escape.

## Known integration limits

Headless tests exercise archive serialization, actual shape code, bitmap render channels, snapshot swapping, shortcut routing, and gesture resets. They do not dispatch undo through a live GH_Document, validate GH's native mouse-interaction ordering, or demonstrate DPI/OS integration. Mixed native-object movement and multi-component ownership require particular attention. Unknown payload preservation consumes memory proportional to that payload; parser budgets bound interpretation rather than archive loading performed by GH itself.

## Independent review follow-up checks

1. Put a future-format/read-only HopperDraw before an editable one in document order. Select the read-only component and leave it first. The editable component must still draw and edit when it is the eligible owner; the read-only component must never capture double-D or mouse input.
2. Group a readable line with an opaque child, including one nested group. Attempt body/handle/multi-selection drags: no selected geometry or native pivot may move, no undo record should be added, and a blocking warning should appear. Ungroup to expose the opaque child, use Select unreadable annotation records and Delete, then Undo/Redo its removal and confirm original raw data and order.
3. Remove only the HopperDraw annotation chunk from a saved GHX while leaving valid GH metadata. Reopen: expect an empty editable annotation component and a one-time pre-v1 notice; draw/save/reopen normally. No GH metadata should appear inside the new annotation chunk.
4. Remove a shape style field or a component style field from a GHX copy. Defaults should be safe and warnings should name the missing fields. Make another edit and trigger solutions: component diagnostics must remain. Clear all, Undo, Redo, then read a clean file to check diagnostic lifecycle. Selecting an already-set color/thickness, or styling an all-opaque group, must not dirty the file or add undo history.
5. Add optional unknown items/sub-chunks to a v1 component, shape and child-list chunk. Reopen, edit, save as both GHX and GH, and reopen: values/sub-chunks must survive while edited known values update. A changed major FormatVersion remains opaque/read-only instead. During polyline/curve drafting, vertex squares should appear without a dashed selection path over the preview stroke.

The automated hook suite additionally stages a failing marker while its working file passes, stages a passing snapshot while its working files/verifier fail, checks pushed refs different from HEAD, multiple refs, duplicate tips and deletions, and compares index/working/untracked contents before and after.

## Canvas UX

All checks in this section are **live-only and not yet executed**. Headless InputRegression verifies selection decisions, absolute annotation proposals/rollback, draft transitions, angle snapping, stroke window/crossing, channel/owner/shape hit order and pen stickiness. Serialization verifies menu state/actions, no-op boundaries, and multi-owner snapshot swaps. ShortcutRouting runs a real Windows message loop for pre-mouse ordering, native double-click ordering, Delete/Ctrl+A before menu preprocessing, repeated Escape, right-drag message delivery, and capture loss. Its pan transport fixture does not instantiate GH pan/zoom; none of these tests prove GH undo dispatch or native interactions.

1. **Claiming and precedence:** draw under/over native objects with two owners, in both document orders. Selected handles must win narrowly; elsewhere native objects win, then Overlay annotations, then Groups annotations, then later owner/shape. A GH group interior remains empty canvas (pick, right-click, hover and draw inside groups, including nested and blob-shaped groups); its edge band remains native, even where an annotation stroke crosses it (selected handles still win). Press Escape while holding the mouse mid-polyline: the whole draft is discarded in one press. With a preview boundary active, Escape clears it first, even during an annotation gesture. Move from an annotation straight onto a grip: GH's wire cursor must appear immediately. With annotations selected, start a wire from an unselected component's grip, drag a slider and click a toggle: the annotation selection must survive. Click an unselected component: it must replace both selections. Hover grips/wires/sliders: GH's own cursors must not be overridden. Test MRU/no-document panels, abort/cluster icons, Ctrl+Alt information mode, preview-boundary recording, widgets, native active objects, and an existing native interaction: annotation input must yield. Aborted documents conservatively yield everywhere; inside clusters the top-left 100 DPI-scaled pixels are reserved because the pinned API exposes no icon hit test.
2. **Selection:** exercise plain, Shift, Ctrl, Shift+Ctrl clicks on selected/unselected annotations in two owners. Press a selected annotation with native components selected: preserve everything. Press an unselected native object plainly: clear annotations. Press a selected native object or use modifiers: preserve annotations as specified. Handles edit only their shape.
3. **Window/crossing:** select long lines whose endpoints lie outside the rectangle, closed-polyline closing edges, and curves whose extrema exceed their controls. Window must contain the whole stroke including thickness; Crossing must touch actual strokes, not frame interiors/group bounds. Sample modifiers at release: Shift add / Ctrl remove / Shift+Ctrl replace. Escape or replacement of GH's actual window session must not select annotations. Plain empty click clears them.
4. **Annotation-led mixed movement:** include two owners, a selected native group with nested groups, sliders, panels, components and wires. Drag a selected body with and without Shift. Movement is absolute from press snapshots; native group descendants follow once. One Undo/Redo restores all shapes/pivots/layouts, with no extra move record. Click/no movement and moving back to start produce no annotation record/dirty flag. Include an opaque descendant: all selected annotation geometry and annotation-led native pivots must stay put, with a warning.
5. **Native-led follow:** repeat by dragging native bodies and GH group edges. Verify snap guides, Shift, auto-pan in all directions, and both annotation channels. Toggle Alt repeatedly during one drag: annotations return to start in copy mode and follow originals again in move mode. Release in copy mode: only native objects copy. One Undo/Redo of a native move includes annotations across owners. GH snapping back/no matching drag record must not leave unrecorded annotation movement or attach to an unrelated undo record.
6. **Cancellation/lifecycle:** Escape restores every pivot/annotation immediately, with no record. A plain native drag with no selected annotations must behave exactly like stock GH on focus/capture loss. Middle-click (radial menu), Alt-Tab and Pen > Custom... between polyline clicks must keep the draft. Repeat during annotation/native drags with focus loss, capture loss, document switching, component removal, disabling/hiding/locking an owner, closing/reopening documents, and canvas handle recreation. Afterward a fresh drag, double-D, and undo must work once each. Auto-pan must stop on every exit. Verify no retained hooks or callbacks after the last owner is removed.
7. **Keyboard:** with only annotations selected and with a mixed selection, Delete/Backspace removes the expected objects in one record, including when a selected HopperDraw owner is itself removed. Undo/redo must restore removed owners, their shapes, wires and surviving-owner shapes. With no annotations selected Delete stays native. Ctrl+A selects both and Ctrl+D deselects both while GH still runs its own Select All / Deselect All; Ctrl+Shift+A remains GH Grow Selection; test text boxes, numeric editors and menus retain their keys. Held Escape cancels one layer: gesture/draft, then drawing mode, then selection on distinct presses. An Escape already consumed by GH must not exit drawing too.
8. **Context menus/navigation:** right-press leaves selection intact. Right-up selects an unselected shape (Shift adds) and opens only the annotation menu. Right-drag passes its threshold-crossing move to native pan; Ctrl+right-drag to zoom; neither opens a menu nor drops the replacement interaction. Test threshold and menu placement at every DPI. Closing a menu must not leave capture/cursor/interaction state behind.
9. **Menu contents and undo:** verify all eleven swatches, mixed/current checks, session recent colors (max five), Custom…, component-default color, five widths with line previews, five dash previews, uniform-style-to-pen enablement, stable per-owner front/back, single-owner Group explanation, multi-owner Ungroup/Duplicate/Delete. Each changed action is one undo; already-current actions do not dirty or record. Test mixed defaults across owners and nested styles. Component Drawing/Selection menus must agree with canvas menus; no Cycle line type remains.
10. **Drawing/menu tools:** unwired M tool selection updates that input's persistent value with GH undo and expires only its owner. Wired M disables each tool with a tooltip. Right-click empty canvas during drawing opens Tool/Pen/Reset/Exit; elsewhere GH menu remains native. Pen survives creation, cancel, exit/re-entry and selection styling. Explicit Reset restores component defaults.
11. **Drawing gestures:** line/frame press-drag-release and click-click; Shift 45-degree segments and square frames. Polyline/curve click vertices; native double-click and Enter finish open exactly once, no duplicate terminal vertex or trailing-up append; highlighted first-point click closes only after three distinct points. Backspace removes points to cancellation. Shift vertex edits use the preceding vertex; frame corners keep aspect including axis-aligned drags. No GH window selection, deselection or component search during drawing. Non-text annotation double-click outside drawing suppresses search without geometry edits; text now opens the editor (PR2).
12. **Feedback/performance:** at 25/100/400% zoom and 100/150/200% Windows DPI, check pencil/open-hand/closed-hand/handle cursors and clean resets. HUD is bottom-centre in screen space, with the correct tool, pen color/width/dash and relevant hint; first-point closure ring tracks hover. Selected outlines remain legible on white/black/bright strokes and curves; hover is subtle, stored colors unchanged. No idle repaint loop or timers; native auto-pan synchronizes only changed translation before the Groups channel. Repeat with large shape counts and monitor graphics resources.


## PR1: freehand, stroke visibility, fill and hatch (host-only; not yet executed)

Record Rhino/runtime, Windows DPI, plugin commit, and pass/fail. Headless checks cover the model, bitmap clipping, draft processing and transactions; these checks verify actual GH dispatch and display.

1. Confirm the version remains 0.2.0.0 and the seven inputs/GUIDs are unchanged. Feed M=4 and M=99: Freehand must appear in the named values, menus, footer and HUD; 99 warns and clamps to Text (the current maximum); M=4 remains Freehand. A wired M disables tool menu choices.
2. Draw Freehand slowly and with a fast flick at 25%, 100%, 400% zoom and 100%, 150%, 200% DPI. Confirm one open Kind 3 curve on release, exact endpoints, no click/double-click completion, no Shift snapping, and no Enter/Backspace effect while held. Curve must still add vertices per click. Click or make a tiny movement: no shape/undo record.
3. Compare Low/Medium/High smoothing on tight turns, long wobbles and a spiral. Look for severe spline overshoot or stalls. Draw a long stroke beyond 8,192 samples and confirm usable preview/release. Smoothing stays sticky through completion/cancel/exit; a reloaded component starts Medium.
4. Draw a substantial loop and release near the start ring: it closes with no repeated closing vertex and accepts fill. A near-start tiny wiggle or collinear out-and-back must not close. Check the ring and closure match after zoom changes during a held gesture.
5. Hold the pointer at each canvas edge during a freehand stroke. GH auto-pan must continue to add canvas samples even with a stationary screen pointer. Release, Escape, switch focus/app/document, disable/hide/lock/remove the owner, and change tool through wired M while held: every interruption discards the stroke, balances auto-pan, and ignores trailing mouse-up. A fresh gesture must still work.
6. Exercise all Stroke and Fill menu branches, preview bitmaps, recent/custom colors and tooltips. Select open + closed leaves across owners and inside nested groups: Fill changes only eligible closed leaves; checks use that subset; mixed values have no check. Use selection style for drawing requires the entire style tuple to match. Toggle Stroke > None twice to hide/restore the stroke.
7. Set solid fill with color alpha and each opacity. Set each of the ten hatch patterns, all four scales and None/light grey/white/custom backgrounds. Confirm background then hatch ink then stroke order, clean clipping on curves and self-intersections, no hatch outside the boundary, and unchanged canvas phase while panning/zooming and moving viewport edges. Repeat large fills at 25% zoom to check performance and avoid routine solid fallback. Hatch ink stays thin even with an 8-unit or thicker outline.
8. Click filled interiors and hatch gaps, including self-intersecting closed curves. Native GH components/grips retain priority. Unfilled or fully invisible interiors must miss. Crossing wholly inside fill selects it; Window still requires the full boundary and visible stroke, with no enlargement from hidden stroke thickness. Invisible boundaries remain pickable at screen-constant tolerance. With DrawOrder 0 (backdrop), pressing inside a filled frame must start GH window selection over components inside it, and crossing inside it must not select the backdrop; its outline still picks. Zoom far out on a large hatched backdrop: panning and hovering must stay smooth, the hatch fades to a tint without popping, and no seams appear in dense tiled hatches at fractional zoom.
9. Select/hover invisible shapes and enable their owner's drawing mode. Confirm thin dashed boundary ghosts, and selection halo/dashes even with Stroke=None. Complete an open freehand with Stroke=None: a brief no-visible-paint HUD notice, no new shape, no dirty flag or undo entry. A closed loop with a visible fill still completes.
10. Multi-select styled leaves across owners and apply one fill/stroke/hatch command: exactly one native undo record; repeated same value produces none and does not dirty. Undo/redo, duplicate, grouped move, cancelled move and ungroup preserve every style field and stable IDs (duplicates alone rekey). Canvas style actions must not trigger a new solution.
11. Save/reopen .gh and .ghx with all new styles, nested groups and freehand loops. Inspect v1 optional keys and no pen/smoothing persistence. Remove only new keys from a copy: default styles without load warnings. Corrupt a new type/enum/non-finite value: opaque record, persistent warning and exact raw preservation on re-save, including unknown/indexed keys/chunks.


## PR2: text and tool letters (host-only; not yet executed)

Record Rhino 8/runtime, Windows DPI, plugin commit, zoom and pass/fail. Automated model, archive, bitmap and real WinForms-loop tests do **not** verify Rhino's event ordering, native undo dispatch, installed font fallback or IME integration. Version stays 0.2.0.0; format stays v1; all seven input slots and component/assembly GUIDs stay unchanged.

1. **Activation/tool routing:** focus the canvas, release D twice, then immediately T: drawing stays on with Text. Check L/P/R/C/F and HUD letters/menu display hints. Hold each letter: one switch, no repeated cancellation, trailing key-up/WM_CHAR or GH search. Letters outside drawing remain native. Modifiers, held mouse buttons, menus, native grips/sliders/numeric editors and other native interactions prevent switching. DD still chooses the eligible owner and last tool. Wired M shows “Disconnect M to switch tools” and preserves every draft point/held gesture; current-tool reselection preserves the draft. An actual switch discards it and consumes trailing mouse/key-up. Change wired M mid-draft: stay in drawing mode with the new tool.
2. **Placement:** M=5 appears in named values, description, menus, footer and HUD. Click (including tiny movement): point text at the click. Drag both directions and diagonally beyond the threshold: normalized top-left anchor and drag width, independent of drag height; no 45°/square snapping. Release opens one editor. Blank creation/Escape on a blank editor leaves no shape, dirty flag or undo record. Cancel before release and verify no delayed placement. Test auto-pan during text placement.
3. **Display/layout:** at 25/100/400% zoom and 100/150/200% DPI compare Title 48 semibold, Subtitle 28, Body 16, every size preset, Bold and Italic. Test Segoe UI Semibold and message-font fallback on a machine where applicable. Canvas-unit scaling, 1.3 em spacing, 0.4 em padding and box width including padding must be consistent. Explicit blank lines, CRLF/LF, trailing spaces, long words, Unicode/surrogate text and very narrow boxes reflow predictably. Below 3 screen pixels per em, glyphs become grey bars without changing selection/group bounds. Pan a long text and check culling/performance; 100k text and 10k display-line budgets must stay usable.
4. **Editor/key isolation:** type DD and every tool letter; they enter text without activating tools. Enter inserts a newline. Ctrl+A, Ctrl+C/X/V, Ctrl+Z local undo, Delete, Backspace, arrows, selection and IME composition stay in the editor even with parent menus using these shortcuts. Escape/Ctrl+Enter commit once without a trailing character/newline or extra GH command. Native textbox and displayed GDI+ line breaks may differ slightly. Test very small/large zoom and mixed-DPI monitor moves for matched family/style/scaling and sensible overlay bounds.
5. **Commit/focus/navigation:** commit changed text with each exit path (Escape, Ctrl+Enter, outside click, focus transfer): exactly one canvas undo and no solution. Unchanged text, including newline normalization, records nothing. An ordinary outside click still selects/drags/clicks the target. Pan, wheel zoom and Ctrl+right-drag commit on the first viewport change, close the editor and continue navigation; the overlay never follows the changing viewport. Check double-click text in/out of every drawing tool, including immediately after point placement, and Text > Edit text…: one editor and no GH search or stray draft.
6. **Abort/stale identity:** with uncommitted edits, invoke host undo/redo, switch documents (also via tabs), disable/hide/lock/remove the owner, close the canvas and remove the last registered owner. Abort without writing the buffer or adding undo; restored text must never be overwritten by a later lost-focus/queued callback. Repeat for text inside two nested groups and after move/undo snapshot swaps. End/restart editing and verify DD starts fresh. Switch between two canvases/documents and owners; at most one editor per controller.
7. **Transactions/geometry:** new blank is discarded; clear existing text to whitespace and commit: one delete undo; changed text: one edit undo; unchanged text: none. Undo/redo restores every text, glyph and box style field and stable GUID. Drag text bodies with mixed native/annotation selection, cancel/return to start, duplicate and nested group/ungroup. Right-edge handle alone adjusts width while anchor stays fixed, converts point text to box text, reflows, ignores Shift snapping, and creates no record for unchanged width. Group bounds, hover, outline and window/crossing include the measured layout (including blank lines/padding). Overlay text interiors pick with Stroke=None/Fill=None; backdrop text only picks at the box edge and preserves native priority.
8. **Styles/menus:** Text > Style/Size/Bold/Italic/Color/Edit text… agrees between component and shape menus. Mixed selections across owners/groups affect only text leaves in one record; mixed text fields have no check. Switching preset resets size/Bold/Italic as documented and retains glyph/border/fill/hatch colours. Choose blue glyphs, red border and a hatch/background: fill/hatch, border, glyph paint order is correct. Stroke=None never hides glyphs. Point and box text both draw their padded layout box. Text > Color/component default affects glyphs only; Stroke > Color affects border only. Check named/recent/custom palette and menu resource cleanup.
9. **Pens/persistence:** set Text pen typography/colour/box styling, switch to Line and back: geometric stroke remains visible and text defaults remain sticky. Uniform text selection style copies into the text pen; mixed typography disables copying. Reset resets both pens. Reload creates default session pens. Save/reopen .gh/.ghx with point/box text in nested groups, extensions and every field: Kind 5/one anchor roundtrips. Missing optional keys default silently; invalid type, width, enum, size, anchor cardinality or excessive text stays opaque and re-saves intact. Unknown/indexed extensions survive text edits/clone/undo. Kind 4 groups and Kind 3 freehand remain readable; an older v1 reader retains Kind 5 opaque.
